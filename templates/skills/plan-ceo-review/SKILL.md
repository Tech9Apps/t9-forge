# /plan-ceo-review

Reframe the request from a product/outcome perspective before implementation.

## Instructions

### 1. Reframe the job-to-be-done
- Identify the real user problem behind the request.
- Distinguish requested feature vs desired user/business outcome.

### 2. Raise ambition level
- Propose a stronger "10x" version of the outcome.
- Call out what would make the experience feel inevitable, not incremental.

### 3. Pressure-test product risk
- Identify adoption risk, trust risk, and differentiation risk.
- Identify what should be validated before engineering effort.

### 4. Produce decision-ready output
- `Current request`
- `Reframed opportunity`
- `Recommended scope now`
- `Deferred ideas`
- `Validation plan`

### 5. End with execution handoff
- Ask whether to proceed to `/plan-eng-review`.

Planning only. Do not implement code from this skill.
