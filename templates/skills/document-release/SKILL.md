# /document-release

Update project documentation so it matches shipped behavior.

## Instructions

### 1. Analyze release scope
- Review commits/diff since base branch.
- Identify behavior and API changes that affect docs.

### 2. Locate affected docs
- `README.md`, architecture docs, contribution docs, command references, changelog.
- Skip files unrelated to shipped changes.

### 3. Apply documentation updates
- Prefer precise edits over broad rewrites.
- Keep voice and terminology consistent with repository conventions.

### 4. Verify consistency
- Ensure commands, paths, and workflow names match actual repository artifacts.
- Flag uncertain changes for user confirmation.

### 5. Output
- Files updated.
- Material behavior changes captured.
- Remaining doc debt.
